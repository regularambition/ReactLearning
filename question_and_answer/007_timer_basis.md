# 各種のタイマー処理を理解する

## window.setInterval

一定の時間間隔で同じ処理を反復して欲しい場合に利用する

```
window.setInterval(handler, intervalLength);
```

という形で利用するのが基本

- `handler` ： 実行して欲しい処理（関数の形で渡すのが基本）
- `intervalLength` ： 反復時間間隔（ミリ秒単位の整数値）

返される値は整数値でこれを`id`と呼ぶことにすると、`id`を記憶しておいて、後で

```
clearInterval(id)
```

として呼び出せば二度と`handler`の処理を行わないようにすることができる<br>
handlerの初回実行タイミングは`window.setInterval`の評価が終わってから<br>
`intervalLength`ミリ秒だけ経過した時点であり、

```
id = window.setInterval(handler, 1000);
```

というプログラムがある時、上記の行に到達して評価が終わった時点では<br>
`id`に`clearInterval`用の整数値が記録されているだけではなく<br>
1秒後に`handler`の初回実行が走り、以後1秒間隔で繰り返されるようになる

## window.setTimeout

一定時間経過後にある処理を一度だけ実行して欲しい場合に利用する

```
window.setTimeout(handler, delay);
```

という形で利用するのが基本

- `handler` ： 実行して欲しい処理（関数の形で渡すのが基本）
- `delay` ： 遅延時間（ミリ秒単位の整数値）

返される値は整数値でこれを`id`と呼ぶことにすると、`id`を記憶しておいて、後で

```
clearTimeout(id)
```

として呼び出せば`handler`の予約を取り消すことができる<br>
実行タイミングは`window.setInterval`の時と同様に考えられる

## Date.now() と performance.now() の違い

| 項目                         | `Date.now()`                                  | `performance.now()`                                    |
| ---------------------------- | --------------------------------------------- | ------------------------------------------------------ |
| **基準点（タイムオリジン）** | Unixエポック<br>（1970年1月1日 00:00:00 UTC） | `Performance.timeOrigin`<br>（ページ読み込み開始など） |
| **返却値の意味**             | 絶対時間（壁時計時間）                        | 相対時間（経過時間）                                   |
| **精度**                     | 通常ミリ秒（整数）                            | サブミリ秒（小数点付き、最大マイクロ秒精度）           |
| **単調増加性**               | なし（時計が戻ることがある）                  | あり（必ず増加する）                                   |
| **システム時計の影響**       | 受ける（NTP同期や手動変更でズレる）           | 受けない                                               |
| **主な用途**                 | 日付・時刻の記録、ログ、サーバー連携          | 処理時間の計測、アニメーション、FPS計算など            |
| **TypeScriptの戻り値型**     | `number`                                      | `DOMHighResTimeStamp`（実質 `number`）                 |
